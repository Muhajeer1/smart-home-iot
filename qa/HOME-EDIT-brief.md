# HOME-EDIT — редактирование своего дома

## Рабочая задача

Владелец хочет исправить название или адрес уже созданного дома, сохранив комнаты, устройства и историю. Реализовано локально; Vercel не обновлён. Тестировщик самостоятельно готовит checklist, выбирает test cases, выполняет UI/API/SQL проверки и оформляет найденные дефекты. Наличие дефектов не гарантируется.

## Acceptance criteria

1. На /homes в My Homes доступны название, адрес и кнопка Edit каждого своего дома.
2. Edit открывает форму с текущими названием и адресом. Открытие другого дома заменяет несохранённый черновик его значениями.
3. Cancel закрывает форму без сохранения. Обновление страницы также теряет несохранённый черновик.
4. Save Changes сохраняет оба поля. После успеха форма закрывается, список показывает обновлённые значения, сообщение — Home updated successfully! Изменения сохраняются после обновления страницы.
5. Оба поля — обязательные строки. Крайние пробелы удаляются. После удаления пробелов название содержит 1–60 символов, адрес 1–200. Длина считается в Unicode code points. Внутренние пробелы сохраняются. Буквы, цифры и специальные символы допустимы и отображаются как текст.
6. Во время сохранения форма заблокирована от повторной отправки. При ошибке сохраняется введённый текст, показано сообщение; форму можно исправить и отправить повторно.
7. Изменять дом может только его владелец, определённый по сессии, независимо от роли. Чужой и несуществующий дом дают одинаковый 404. Отсутствующая/недействующая сессия — 401.
8. Сохраняются прежние home_id, owner_user_id, created_at и все связи с комнатами/устройствами. Переданные дополнительные поля, включая owner_user_id, игнорируются. Новая запись Home не создаётся.
9. Сохранение без изменения значений разрешено. При одновременных сохранениях остаётся последняя успешно записанная версия.
10. Отдельное событие редактирования в Event в этой версии не создаётся. Новые правила длины относятся к редактированию; создание дома в эту задачу не входит.

## API contract

- PUT http://localhost:3000/homes/:id
- Cookie token из POST /login; Content-Type: application/json.
- Обязательные поля JSON: home_name (string), address_text (string). Оба нужны даже при изменении одного поля.
- id — положительное целое число, записанное десятичными цифрами без ведущих нулей, максимум 2147483647.
- 200: {"message":"Home updated successfully","home":{...}} — обновлённая запись дома.
- 400, error: Invalid home ID.
- 400, error: Home name is required. / Address is required. — отсутствие, null, пустая строка или пробелы.
- 400, error: Home name must be a string. / Address must be a string. — неверный тип.
- 400, error: Home name must be at most 60 characters. / Address must be at most 200 characters.
- 401, error: Please log in again.
- 404, error: Home not found.
- Поля проверяются в порядке home_name, address_text; возвращается первая ошибка. Проверка сессии предшествует валидации тела.
- Если существующее ограничение уникальности в БД отклоняет сохранение, возвращается 409 с error; новые ограничения уникальности эта функция не вводит. Фактические ограничения локальной БД требуют уточнения перед соответствующими проверками.
- При сетевой ошибке UI: Unable to save home. Please try again. При потере ответа результат записи может быть неизвестен — следует перечитать данные.

## Окружение и данные

Запуск из папки проекта: npm run dev. UI: http://localhost:3000/homes. Postman Desktop. PostgreSQL: локальная smart_home_test при текущей конфигурации .env.

Основная таблица: "home"; поля home_id, owner_user_id, home_name, address_text, created_at. Владельцы: "User". Используйте собственные тестовые дома; существование учётных записей и их ID подтверждается в текущем окружении.

## Передача в QA

Выполнены синтаксические проверки JavaScript и изолированные разработческие проверки обработчика с подменой БД. Полная браузерная приёмка и проверка записи в настоящую PostgreSQL остаются задачей тестировщика. Код ранее найденного дефекта событий в рамках этой задачи не менялся.
